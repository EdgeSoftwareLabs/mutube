# YouTube + on iPhone and iPad

A native app (SwiftUI, WKWebView, AVFoundation) that opens `https://m.youtube.com`
full screen and injects a userscript bundled into the app. Nothing is loaded
from a CDN at runtime. iOS 16.0 or later.

Display name **YouTube +**. Publisher **Edge Software Labs LLC**. Bundle id
`com.edgesoftwarelabs.youtubeplus` (change it in `Config/YouTubePlus.xcconfig`
if a personal team or Sideloadly needs a different one).

## Architecture

Same idea as the Tizen bundle: the script is copied into the app at build time
and injected by the shell, instead of being fetched when the page loads.

| Piece | Role |
|---|---|
| `js/youtube-plus-ios.js` | Source of the injected script. Hooks `JSON.parse`, `fetch`, and `Response.prototype.json`, then strips InnerTube ad payloads without walking thumbnail metadata. |
| `js/content-rules.json` | `WKContentRuleList` rules for doubleclick, googlesyndication, googleadservices, pagead, ptracking, and ad stats. Image requests (thumbnails) are not in the rule list. |
| `js/open-url.js` | `youtubeplus://` parsing and the Safari "open in YouTube +" decision. |
| `YouTubePlus/Resources/` | The copy Xcode puts in the app bundle. Regenerated by `platforms/build_platforms.py ios`. |
| `YouTubePlus/*.swift` | The shell: persistent `WKWebsiteDataStore.default()`, safe areas, settings, audio session. |
| `YouTubePlus.xcodeproj` | Open this in Xcode. No extra generator. |

Tab switches (Home, Subscriptions, Shorts, You) stay responsive because the
script only walks the feed structure of an InnerTube response. Thumbnail
objects, tracking params, and `responseContext` are left alone, the content
blocker does not inspect image loads, and the web view keeps a large URL cache
plus preconnects to `i.ytimg.com`. The userscript runs in the main frame only.

`WKUserScript` runs the bundle at **document start** (so hooks exist before
YouTube's own scripts) and calls `YouTubePlus.boot()` at **document end**.
The native settings sheet writes `window.YTPLUS_CONFIG` before the script and
calls `YouTubePlus.applySettings` when a toggle changes.

Home-feed menu items are not rewritten. **Not interested** and **Don't recommend
channel** stay as YouTube sends them.

## Features

- **Ad Block** (on): content rules plus InnerTube filtering, and a DOM fallback that clicks skip and jumps a short ad video to the end.
- **SponsorBlock** (on): sponsor, intro, outro, self-promotion, and interaction reminders, each with its own toggle. A small toast names the segment that was skipped. Uses the public SponsorBlock API only while the feature is on.
- **Background Play** (on): `UIBackgroundModes` = `audio`, `AVAudioSession` category `.playback` and mode `.moviePlayback`, set before playback and again when the app resigns active. While the screen is locked the page keeps reporting visible, YouTube's visibility listeners are dropped, and a background task calls `play()` again at 0, 250, and 750 ms if the user had not paused. Coming back, a video that is still stalled after 1.5 s is nudged once. None of that runs during ordinary foreground playback.
- **Lock screen and Control Center**: play, pause, skip back 10 seconds, skip forward 10 seconds, and scrubbing. Next and previous track are disabled so iOS shows the 10-second buttons. The page reports title, channel, thumbnail, duration, and position. Picture in Picture stays available to the system when that setting is on; there is no PiP button.
- **DeArrow** (off): replaces clickbait titles and thumbnails with community submissions. The settings row uses the same explanation as the TV app: "DeArrow replaces clickbait titles and thumbnails with community-submitted, more accurate ones."
- **Return YouTube Dislike** (off) and **Hide Shorts** (off).
- **Debug Logging** (off): script logs are forwarded to the Xcode console.
- First launch shows a **Welcome to YouTube +** toast at the top right, then never again.
- Google sign-in stays inside the app (`accounts.google.com` and the YouTube hosts). Other links open in Safari. Swipe back and forward, pull to refresh, and rotate to landscape for video. The page sits in the safe area; the notch, Dynamic Island, and home indicator are black (`#000000`) with the page background `#0F0F0F`.

Ad Block, Picture in Picture, DeArrow, and Hide Shorts rebuild the web view so the new document-start configuration applies. SponsorBlock, Background Play, dislike counts, and debug logging apply immediately.

**YouTube + Settings** is a row in YouTube's own settings list (avatar or You, then Settings), cloned from a category row so it keeps that row's padding, type, and chevron. It sits with General and History & privacy, above the "YouTube, a Google company" footer. Tapping it opens the native sheet. If that list is not on screen, the same row is added to the account menu instead, and it is put back after YouTube redraws the page. A two-finger long-press still opens Settings. There is no separate header button. The sheet's switches use YouTube's own on and off colors. Settings live in `UserDefaults`.

Search history removals are stored in the web view. A suggestion you remove stays gone when you leave and reopen search, and the app also sends YouTube's feedback delete. The search screen uses the same dark background (`#0F0F0F`) and light text as the rest of the app.

The in-app UI does not say TizenTube and has no social or support links. Credit for the TV userscript this project grew out of stays in the repo [NOTICE](../../NOTICE) and the root README.

## Build the script bundle (Linux or macOS)

```bash
python3 platforms/build_platforms.py ios
```

That syntax-checks `js/youtube-plus-ios.js` and copies it, plus `content-rules.json`, to `YouTubePlus/Resources/`. `make test` runs `tests/ios-script.js` against the script (ad stripping, menu preservation, SponsorBlock, the visibility shim, the settings bridge) and checks the copy matches.

## Build an unsigned IPA (macOS, Xcode)

```bash
platforms/ios/build.sh
```

On Linux the script only refreshes the JS bundle and tells you to finish on a Mac. On a Mac it runs `xcodebuild` with code signing turned off and writes:

```text
platforms/ios/build/YouTubePlus-unsigned.ipa
```

Open `platforms/ios/YouTubePlus.xcodeproj` in Xcode if you would rather sign with your own team. Set `YTPLUS_TEAM_ID` (and, if the id is already taken, `YTPLUS_BUNDLE_ID`) in `Config/YouTubePlus.xcconfig`, select the YouTubePlus scheme and your iPhone, and press Run. The Xcode target's Run Script phase copies `js/` into `Resources/` before the app is packaged, so a normal Run picks up script edits.

## Sideload

The unsigned IPA is meant to be re-signed. It contains `YouTubePlus.app` and `PlugIns/YouTubePlusSafariExtension.appex`. Both use `Config/YouTubePlus.xcconfig` (`YTPLUS_BUNDLE_ID`, `YTPLUS_TEAM_ID`); the extension's id is `$(YTPLUS_BUNDLE_ID).safari-extension`. The App Store YouTube app can stay installed; this bundle id is different.

**Sideloadly**

1. Install [Sideloadly](https://sideloadly.io/) and plug in the iPhone.
2. Drag `platforms/ios/build/YouTubePlus-unsigned.ipa` into the window.
3. Sign in with an Apple ID. A free personal team expires after 7 days; refresh the install the same way.
4. Start. If the bundle id collides with another sideloaded app, change `YTPLUS_BUNDLE_ID` in `Config/YouTubePlus.xcconfig`, run `platforms/ios/build.sh` again, and repeat.

**Automatic Sideloader**

Import the same unsigned IPA and sign it with your Apple ID. The display name is already YouTube + and the bundle id is `com.edgesoftwarelabs.youtubeplus`.

**Xcode**

Open the project, set the team in the xcconfig (or in Signing & Capabilities), and run on the device. That produces a signed install directly and does not need the IPA. The YouTubePlus scheme builds the Safari extension and embeds it.

## Open YouTube links from Safari

Optional. The app registers `youtubeplus://`. The embedded Safari extension **Open in YouTube +** sends `youtube.com`, `m.youtube.com`, `www.youtube.com`, and `youtu.be` pages to `youtubeplus://open?url=...`, including a watch page opened from Google Search and a cold launch. iOS often ignores a custom-scheme redirect that is not tied to a tap, so the page also shows an **Open in YouTube +** banner and hands off a tap on the player or a video link. The extension popup has **Open Current Page in YouTube +** for a page that is already open. Sign-in and OAuth pages (`accounts.google.com`, `accounts.youtube.com`, `/signin`) are not redirected. An automatic attempt does not repeat for the same URL within a few seconds, so a blocked handoff cannot reload in a loop.

On a watch page in portrait, YouTube + keeps **Home**, **Shorts**, **Subscriptions**, and **You** in a bar at the bottom of the page. That bar hides in landscape and fullscreen. The mobile site's **Open App** pill is hidden.

1. Install YouTube + (the IPA above, or Run from Xcode).
2. On the iPhone open **Settings → Safari → Extensions**.
3. Enable **Open in YouTube +** and allow it on youtube.com.
4. Tap a YouTube link in Safari, including a result on Google. It opens in YouTube +. If Safari keeps the page, tap **Open in YouTube +** on the banner, or use **Open Current Page in YouTube +** in the extension popup.
5. To keep a link in Safari, open the extension's button and turn off **Open YouTube links in YouTube +**. Turn the extension off entirely from the same Settings page.

The extension's `images` directory is an Xcode folder reference, so `images/icon-128.png` (and the other icon paths in `manifest.json`) stay in that subdirectory inside `YouTubePlusSafariExtension.appex`. Loose file references would be copied to the root of the extension and Safari would report them missing.

Icons are the catalog in `Assets.xcassets` (from `icons/png/youtube-plus-1024.png`). YouTube is a trademark of Google LLC. This app is not affiliated with or endorsed by Google.
